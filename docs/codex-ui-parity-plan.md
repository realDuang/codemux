# Codex 展示能力对齐：调研、改造计划与多引擎兼容要求

这份计划以官方本地编码会话为参照，改进 CodeMux 的思考摘要、过程说明、回复、工具活动、流式 Markdown 和历史恢复。**共用一套展示组件，同时保留各引擎原有的会话与消息语义。** OpenCode、Copilot、Claude、Codex CLI 和 Codex Desktop 都在兼容范围内。

功能行为与 UI 样式分开推进。功能基线列在“当前实现范围”中；S01–S12 已按本轮批准的范围实施，结果见“样式实施与验收记录”。下文的思考内容指引擎实际提供、允许展示的文本；不能据此承诺取得模型未公开的内部推理。

公开的 app-server 协议没有规定全部 UI 行为。Desktop 会把协议事件转换为私有展示模型，再根据本地偏好、产品模式和功能开关选择呈现方式。因此，目标是对齐指定模式下可验证的行为，不能把所有 Desktop 模式视为同一种界面，也不能要求不同引擎使用相同协议或输出相同思考内容。

### 基础行为与条件分支

| 展示场景 | 静态代码能确认的行为 | CodeMux 的取舍 |
| --- | --- | --- |
| 本地编码会话 | 原生 item 转换为按顺序排列的用户、助手、活动、计划和资源块。思考正文与活动标题使用公开 summary sections | 作为主要行为参照，保留原生身份和事件顺序 |
| 仅显示最新 commentary | 显式设置 `commentaryDisplay: latest` 时，符合条件的最新 commentary 作为进度；后续 final 或 async 输出会清除它。轮次组件自身没有把该属性默认设为 `latest` | 作为独立展示选项。适配器不得因此删除早期 commentary，也不能认为所有用户都默认使用此模式 |
| 活动折叠 | 被检查的分组组件在没有额外指定时默认折叠；详情折叠期间，活动标题仍可变化 | 每段活动独立折叠，保留用户选择 |
| 完整记录与 compact/Aeon | `showFullTranscript`、会话类型和开关会改变展示转换；一个紧凑分支隐藏尚未完成的 final 文本，改为显示 `Typing…` | 不将紧凑模式的 final 文本抑制规则套到本地编码会话 |
| 日常表述（`STEPS_PROSE`） | 部分命令、文件标签采用非技术表述；例如摘要用 `Running command` 代替命令原文 | 命令详情始终可查。是否增加这种偏好，应单独作产品决定 |
| 内嵌应用、生成产物、反馈与专用卡片 | 依赖额外数据、服务和开关；归档里存在渲染器，并不能证明公开 CLI 会话可用 | 逐项记录支持情况。能力或数据缺失时，退回可读内容 |

### 实现边界

- Codex 协议的特殊解释放在 Codex 适配器。共用 UI 只读取统一字段和 `EngineCapabilities`，不能增加按 `engineType` 或 `engineMeta` 分支的渲染逻辑。
- 继续使用现有 SolidJS、marked、Shiki、文件服务和状态存储。只有明确差距需要时才引入依赖；本计划不要求通用渲染器注册中心或第二套会话模型。
- CLI 和 Desktop 归一化后共用渲染器。Desktop 私有资源、开关及交互回调仍要单独检查数据和能力。
- 没有 phase 的 OpenCode、Copilot、Claude 消息保留现有回退行为。共用组件的改动必须覆盖跨引擎回归，不为每个引擎复制一套界面。

## 多引擎兼容：哪些必须一致，哪些保留差异

一致的是可读性、操作方式和状态准确性；各引擎继续拥有自己的协议、会话、工具执行与可见思考内容。一个引擎没有提供的摘要、耗时、审批历史或资源，不应由 UI 补造。没有可见思考也属于正常结果，界面仍须展示实际进度、工具和回复。

直接复用 [UnifiedPart / UnifiedMessage / EngineCapabilities](../src/types/unified.ts) 及 [message-parts.ts](../src/lib/message-parts.ts)。目前可用的 `TextPart.phase`、`completed`、`ReasoningPart.time`、`compactActivityGroups`、`authoritativeSessionState` 等字段已能表达主要差异。新增字段前先确认现有类型无法表达，且新字段缺省时不改变旧引擎行为。

以下矩阵是实施与验收要求，**不表示五个入口已经全部完成真实运行验收**。每一行都要分别记录单元测试、回放、真实引擎和安装后检查结果。

| 引擎入口 | 保留的消息与思考语义 | 会话、工具和交互约束 | 最小回归场景 |
| --- | --- | --- | --- |
| OpenCode | 由 [OpenCode 适配器](../electron/main/engines/opencode/) 将 SDK 消息、reasoning 和工具转换为统一 parts。保留其实际可见思考；没有 phase 时继续使用旧布局，不能套用 Codex summary-only 过滤 | 保留 OpenCode 的会话 ID、目录、模型选择和工具生命周期。权限选项、取消和历史加载按适配器能力提供 | 同一专用会话中完成一次流式回复、含可见 reasoning 的回放、读／搜索工具和历史重载；覆盖无 phase 文本的原有回复及步骤顺序 |
| GitHub Copilot | 由 [Copilot 适配器](../electron/main/engines/copilot/) 处理 SDK 事件与 JSONL 历史；可见 reasoning 按自己的转换规则保留，缺失时不填入 Codex 式摘要 | 保留会话目录归属、待执行与运行中工具状态、实际权限答复。SDK 流与历史读取不能因共用 UI 改造而重复或丢失消息 | 对照流式结果与重载历史；覆盖工具成功／失败、支持的取消或排队、问题／权限响应，以及无 phase 消息 |

跨引擎还要共同满足以下条件：

- **不丢信息。** 活动折叠和工具合并只改变可见结构，不删除归一化后的正文、子工具、错误或输出。活动状态必须来自真实消息；等待审批和失败不能被“已完成”计数遮住。
- **不改变会话归属。** 切换引擎或会话时，草稿、滚动位置、消息缓存和待答问题不能串到别的会话；回复权限、停止任务或继续会话必须发给原所属引擎。
- **保留旧数据行为。** OpenCode／Copilot／Claude 的无 phase 消息继续使用现有最后文本回复布局。Codex 紧凑视图没有显式 final 时，仅在轮次正常结束且最后可见文本没有 phase 时使用该文本作为兼容回复；其余内容保留在步骤中。旧会话不因升级重新排序或多出空思考卡片。
- **不扩大资源权限。** Electron 的 `file:` 入口与认证 Web／PWA 入口都通过现有文件服务访问服务端资源；保持 Server／Desktop 的运行边界和既有授权规则。
- **差异可解释。** 能力未提供时隐藏不可用动作或显示可读回退；单独的引擎适配失败不能让其他已连接引擎的会话失效。英文、中文、俄文文案同步，操作能用键盘和触控完成。

## Codex 整轮步骤折叠补充

Codex 紧凑视图折叠整轮步骤时，commentary、partial、思考、工具、提示和独立工具附件一起收起。用户问题和全部最终回复片段保留，最终文本里的 `inlineAssets`、来源和复制内容也保留。再次展开后按原始时间顺序显示全部过程，内层工具详情仍可单独展开。

没有手动操作时，运行中的轮次默认展开，完成后默认折叠。手动展开或折叠的状态在轮次完成后仍保留，新文本或工具更新也不覆盖它。步骤入口也适用于没有 `stepCount` 的实时消息和已完整加载的历史，加载完成后仍能重新收起过程。

`completed` 只说明当前 item 已完成。commentary 和 partial 不因此成为最终回复；没有 final 的轮次通过步骤查看过程，已有的运行状态、待答问题和错误入口继续可用。缺少 phase 的兼容回退仅用于正常结束轮次的最后可见无 phase 文本，失败或中断时不把过程文本提升为回答。OpenCode／Copilot／Claude 保留既有展示和折叠行为。

在 [UI 回放夹具](../tests/fixtures/ui-parity/README.md#compact-turn-folding-stream) 的 Codex CLI 或 Codex Desktop 会话输入 `folding-stream`，可先看到约 3 秒的 commentary 更新和已完成的 partial，再进入思考、工具及最终回复。该场景不带 `stepCount`，用于检查默认收起、手动选择保留和 `STREAM_COMPLETE` 的完整显示；它不调用真实提供商。

## 官方 Desktop 升级后的复查方法

升级后重新计算归档和成员哈希，并重新定位锚点，再复用上述观察。现有 `@electron/asar` 依赖足以完成只读检查，无需对运行中的应用插桩。

```js
const asar = require("@electron/asar");
const { createHash } = require("node:crypto");
const archive = "/Applications/ChatGPT.app/Contents/Resources/app.asar";
const member = "webview/assets/sites-end-resource-78b98c374310.js";
const bytes = asar.extractFile(archive, member);
const source = bytes.toString("utf8");
console.log(createHash("sha256").update(bytes).digest("hex"));
console.log(source.indexOf("function qT(")); // UTF-16 code units
```

提取的官方文件保存在仓库外。[REA](https://github.com/morluto/rea) 的静态清单和调用追踪可辅助定位改名、压缩后的模块；匹配到字符串或找到渲染器，还需要沿调用链确认对应产品模式是否使用它，并区分基础行为和条件分支。
